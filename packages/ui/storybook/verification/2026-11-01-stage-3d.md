## Problems found and fixed

1. **Message names ran together.** Adjacent spans gave the accessible name “AlexMentor18:04”. The name now comes from separate ids joined by `aria-labelledby` (unit test).
2. **The composer took focus on the first render** when a reply was already set, which would make a page or the docs jump. Focus now moves only when the reply target changes (unit test).
3. **The session screen declared its shell component inside render**, which would remount the composer and lose text and focus on every change. It is now a function call.
4. **MDX tables split over lines failed to index** (a known stage-1 lesson); they are now one JSX block each.
5. **A layout play test assumed a single column**, so it failed when the story opened at 1440 px without the viewport global. It now checks reading order always, and the vertical position only below `xl`.
6. **Earnings totals in the 45-row story were wrong** (7,440 instead of 7,200); corrected before the first run.

## Findings for your decision

- **The table scrolls at 320 px.** The approved Table rule keeps cells on one line, so on the earnings and “My sessions” lists only the date column is visible at 320 px and the rest scrolls. The approved four-column limit does not prevent that once the first column holds a full date. Proposal: a shorter date format inside tables (“4 Nov, 18:00”), or let the first column wrap.
- **Axe best-practice findings on seven older docs pages:** `landmark-unique` and duplicate `main`/`banner`, because several full-page stories are stacked on one docs page. These are not WCAG failures and are not new. Stories tested alone pass.
