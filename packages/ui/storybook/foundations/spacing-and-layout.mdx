# Spacing and layout

Pick a relationship first, then the token. Dense lists and a conversation with priority are different layouts, not competing global density modes. Sources: R01.1, R02.1, resolved reference conflict.

<table><thead><tr><th>Relationship</th><th>Token</th><th>Value at the default root size</th><th>Example</th></tr></thead><tbody><tr><td>Within a group</td><td>--space-within-group</td><td>8 px</td><td>Author and timestamp</td></tr><tr><td>Between groups</td><td>--space-between-groups</td><td>16 px</td><td>Labelled field groups</td></tr><tr><td>Inside a panel</td><td>--space-panel</td><td>24 px</td><td>Booking summary padding</td></tr><tr><td>Between sections</td><td>--space-section</td><td>32 px</td><td>Public work and availability</td></tr></tbody></table>

Source: approved token table (R01.1/R02.1/R02.3). Do not use panel padding for every dense table cell. Retained smaller spacing tokens support the current component anatomy; relational tokens govern new compositions.
