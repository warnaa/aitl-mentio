# Motion

A transition tells you what changed and where. It never delays the result. Feedback stays beside the changed element; an extra toast must not repeat that information. Sources: U02.1, R02.4.

Use `--default-transition-duration` (150 ms) and `--default-transition-timing-function` for brief color or border transitions. Do not add decorative scale, slide, bounce or continuous animation to a success message. Source: approved token document, U02.1. This example saves local demonstration state immediately; it does not simulate a successful API write.

When `prefers-reduced-motion: reduce` is active, remove nonessential transition time through `--motion-reduced-duration`. The visible message remains. Sources: task Foundations motion requirement and [WCAG animation guidance](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html). The retained spinner in LoadingMessage is reviewed with its component in stage 2; this page does not certify all existing animations.

The Foundations checks include a click interaction and a reduced-motion rule assertion. Test the actual asynchronous flows separately when API patterns arrive in stage 3. Source: task stage 3 form outcomes.
