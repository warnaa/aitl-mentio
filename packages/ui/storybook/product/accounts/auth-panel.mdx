# AuthPanel

## 1. Purpose

Frame a single account task (sign in, create an account, become a mentor) in one readable column. Sources: accounts UI/UX.

## 2. When to use

Use it on the `(auth)` pages `/logowanie`, `/rejestracja` (and `?jako=mentor`), and on `/zostan-mentorem`. Sources: accounts UI/UX.

## 3. When not to use

Use PanelShell for panel screens and MentorDirectory or MentorProfile for public content. Sources: platform F8.

## 4. Anatomy

`main`, named by its `h1` title, with an optional lead, the task (usually CrudForm or one ActionButton) and an optional footer with the alternate link and help. It is at most 28rem wide and start-aligned. Sources: accounts UI/UX; task What to avoid (everything centred).

## 5. Variants

There are no visual variants. Sources: package API.

## 6. States

It is a static frame. States belong to the form or action inside it; see **Product › Platform and accounts › Screens**. The **States** story shows the frame alone; it is not embedded because it would repeat the page's `main` landmark. Sources: package API; verification 2026-11-01 (axe landmark rules).

## 7. Behavior and accessibility

It is a `main` landmark named by its heading, in reading order: title, lead, task, footer. Sources: WCAG 1.3.1, 2.4.6.

## 8. Content

The title names the task: “Sign in”, “Create a mentor account”. The footer link keeps `returnTo`. Sources: accounts UI/UX.

## 9. Responsiveness

At 320 px it fills the width with 16 px padding. Wider screens keep the 28rem column. Sources: approved stage-0 Q3; WCAG 1.4.10.

Also see these stories: **Long Content** (long title and description).
