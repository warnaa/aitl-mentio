# Delete confirmation

Removing something that cannot be restored asks first, names the object and keeps the way out easy, shown with removing an availability slot. Sources: task pattern requirements; mentor-pages UI/UX; platform F5.

## Rules

1. The question names the object: “Remove the slot on Thursday, 6 November 2026, 18:00?” Sources: task pattern.
2. The cancel button is easy to find, receives initial focus and names what is kept (“Keep slot”). Escape cancels. Sources: task pattern; WAI-ARIA APG alert dialog.
3. The confirm button is a verb and object (“Remove slot”), never “OK”. Sources: task pattern.
4. While the request runs, the dialog stays open and both buttons are blocked; a second click does nothing. Sources: platform F3 and F5.
5. On success the row disappears, and a status line says what was removed. On refusal (`409 slot_held`) the row stays and the reason is shown next to the button. Sources: mentor-pages edge cases; reference R02.4.
6. Reversible actions, such as unpublishing, do not ask. Sources: user decision 2026-10-31.
