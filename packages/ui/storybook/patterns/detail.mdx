# Detail

One record with its most important information and its main action visible without scrolling, shown with the booking details. Sources: task pattern requirements; book-and-pay UI/UX.

## Rules

1. The first screen shows the heading, the status, the key facts (time in Warsaw time, length, price in zł) and the main action, even at 320 px with a long body. Sources: task pattern; book-and-pay UI/UX.
2. Long user text keeps its line breaks, and code uses the monospace role. Sources: book-and-pay UI/UX; reference R01.2.
3. “Not found” and “no access” are one state, which does not reveal whether the record exists, with a way back. Sources: task pattern; platform F2 (`notFound()` for wrong owner or role).
4. Loading keeps the layout with Skeleton and a status line. Failure uses ErrorMessage with retry. Sources: batch-4 components.
5. Every booking screen states that the session is text only. Sources: N01; book-and-pay UI/UX.
