# Input

## 1. Purpose

Capture one short value without hiding its label or its editing state. Source: accounts UI/UX; mentor-pages UI/UX; platform F4.

## 2. When to use

Use it for account email/password, a mentor rate in zł, a public-work URL or a native availability date/time. Source: accounts UI/UX; mentor-pages UI/UX; platform F4.

## 3. When not to use

Use Textarea for a question or multi-paragraph description. Use Select for the booking duration; a free-text field would allow unsupported durations. Sources: platform F4, approved component inventory and task How to choose requirements.

## 4. Anatomy

A native input, its opaque neutral surface, boundary, placeholder and focus ring. The visible Label and explanatory/error text come from FormField; they are not Input children. Sources: package API, task field anatomy; WCAG 1.3.1/3.3.2.

## 5. Variants

One visual size: 36 px high, medium 8 px radius, 1 px border. Native text, email, password and number types describe input behavior, not new visual variants. Keep the native datetime control for availability; no calendar variant is added. Sources: approved stage-0 Q2 and package API; no added variants are authorized.

## 6. States

Default, hover and keyboard focus use the neutral surface and full ring. Disabled blocks editing; explain why in persistent nearby text. Read-only retains selectable saved content. Loading is communicated by aria-busy and a visible status; it does not imply a saved value. Error uses aria-invalid plus linked explanatory text. Pressed/selected are not component states: a caret or text selection is native editing behavior. Sources: task stage 2; WCAG 1.4.1/2.4.7/3.3.1; approved contrast corrections and U02.1.

The hover and focus previews use documentation-only data-preview-state attributes wired to the same declarations as real pseudo-classes. Sources: task stage 2 frozen-state requirement; approved Q2.

## 7. Behavior and accessibility

Keep a visible Label with matching htmlFor/id. Tab reaches the input; native selection, arrows and clipboard shortcuts remain available. Use an appropriate type and autocomplete. Link the hint and error through aria-describedby, and set aria-invalid for a real error. The default 36 px control exceeds the 24 px minimum target height; keep sufficient width and spacing. Sources: HTML native control semantics, WCAG 1.3.1/2.1.1/2.4.7/2.5.8/3.3.1/3.3.2/4.1.2.

## 8. Content

Use a short noun phrase such as “Email address” or “Rate per 25 minutes (zł)”. A placeholder is an example, not the name. No universal maximum label length has been approved: wrap the label instead of truncating it. Set maxLength/min/max from the field schema, not from visual convenience. Preserve long entered values and choose inputMode for the value being entered. Sources: U01.1, task Content and longer-language requirements; accounts UI/UX; mentor-pages UI/UX; platform F4.

## 9. Responsiveness

At 320 px, use the available column width and let the label/hint wrap; a long value scrolls within the native input. At 768 and 1440 px, keep a field group readable rather than stretching it because space exists. Do not reduce the approved height or hide the label. Sources: approved stage-0 Q2/Q3; WCAG 1.4.10.

## 11. Code

Minimal association:

```tsx
import { Input } from '@mentio/ui/components/input';
import { Label } from '@mentio/ui/components/label';
<Label htmlFor="email">Email address</Label>
<Input id="email" name="email" type="email" autoComplete="username" />
```

Product composition:

```tsx
import { FormField } from '@mentio/ui/backend/forms';
import { Input } from '@mentio/ui/components/input';
<FormField label="Rate per 25 minutes (zł)" required
  description="Choose a whole amount from 90 to 600 zł.">
  <Input name="ratePln" type="number" min={90} max={600} inputMode="numeric" />
</FormField>
```

The snippets compose real package components; import Input, Textarea and Label from their component subpaths and FormField from `@mentio/ui/backend/forms` when used. Sources: approved import contract; accounts UI/UX; mentor-pages UI/UX; platform F4.

## 12. Good and bad

The bad case is explained rather than rendered as an inaccessible interactive control. Sources: task good/bad and no-accessibility-violations requirements; WCAG 3.3.2/4.1.2.

## 13. Related

FormField owns label/hint/error association; CrudForm owns schema-driven submission. Textarea captures multiline content. Select presents a fixed choice. Sources: approved stage-0 component/pattern inventory, platform F4 and task How to choose.
