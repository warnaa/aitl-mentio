# DataTable

## 1. Purpose

Show a paged list of records from an API with consistent loading, empty, error and refreshing states. Sources: existing `backend/tables`; platform F3; AGENTS.md (lists use DataTable).

## 2. When to use

- The mentee's bookings on `/rezerwacje`.
- The mentor's upcoming slots on `/mentor/terminy`, with a remove action per row.
- The existing admin users list.

Sources: book-and-pay, mentor-pages and accounts UI/UX; existing `/admin/users`.

## 3. When not to use

- For a static table with no loading, use Table.
- For records shown as prose cards, such as the public mentor list, use cards.
- For a single record, use a detail layout.
- Do not reimplement loading, empty and error handling per screen.

Sources: task How to choose (table, list and cards); mentor-pages UI/UX; AGENTS.md.

## 4. Anatomy

Table columns with an optional row-actions column, and an optional pagination row (“1–20 of 45”, Previous, Next). It renders LoadingMessage before the first rows, EmptyState for zero rows, and ErrorMessage with retry on failure. Sources: package API; batch-4 feedback components.

## 5. Variants

There are no visual variants. Optional parts: `rowActions`, `pagination`, and empty-state copy. Sources: package API.

## 6. States

- **First load:** `rows` is `undefined`, and LoadingMessage is shown.
- **Refreshing:** the current rows stay, with `aria-busy`.
- **Empty:** EmptyState with the given title and description.
- **Failed:** ErrorMessage with “Try again” when `onRetry` is given.
- **Paginated:** Previous and Next are disabled at the ends, and during a refresh.

Rows have no hover state. Sources: platform F3 (keep data while refreshing); user decision 2026-10-31 (no row hover).

## 7. Behavior and accessibility

It uses native table semantics. `aria-busy` is set while refreshing. Pagination buttons are real Buttons, disabled at the ends. Unique link names come from the cell content. Loading is announced through LoadingMessage's status, and failure through ErrorMessage's alert. Sources: WCAG 1.3.1, 2.4.4, 4.1.3; WAI-ARIA `aria-busy`.

## 8. Content

The empty title follows the screen spec, for example “You have no bookings yet”. The error message says what to do next. The range reads “1–20 of 45”. Column headers are short nouns. Dates in cells use the short form “4 Nov, 18:00” (user decision 2026-11-01; see Table). The default labels (“Nothing here yet”, “Actions”, “Previous”, “Next”) are English and become Polish with F1. Sources: platform F1; task Content.

## 9. Responsiveness

When the table's own width is below 48rem, each row stacks as a block:
- every value sits under its column name;
- long values wrap;
- the header row is visually hidden but stays for screen readers;
- explicit roles keep the table semantics.

It is a container query, so a table in a narrow column stacks too. At 320 and 768 px (compact layout, Q3) rows stack. At 1440 px the table fills the content column up to 1152 px. The pagination row wraps.

A column whose header is not plain text (for example a visually hidden “Details”) shows no column name; pass `label` to give it one.

Sources: user decision 2026-11-01 (stacked rows, after the 3d measurement); approved Q3; WCAG 1.3.1, 1.4.10; user decision 2026-10-31 (about four columns at most on mobile-first screens).

## 11. Code

```tsx
import { DataTable } from '@mentio/ui/backend/tables';
<DataTable columns={columns} rows={page?.items} getRowId={row => row.id} isLoading={isLoading}
  error={failure?.error.message} onRetry={retry} emptyTitle="You have no bookings yet"
  pagination={{ offset, limit: 20, total: page?.total ?? 0, onOffsetChange: setOffset }} />
```

Sources: existing `admin/users/users-table.tsx`; book-and-pay UI/UX.
