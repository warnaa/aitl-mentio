# Badge

## 1. Purpose

Show a short, read-only status or label next to the object it describes, so a person can scan a list for state. Sources: platform F6 (status badge); book-and-pay UI/UX status labels.

## 2. When to use

Use it for a booking's state in the list and on the detail page, for example “Awaiting payment”, “Awaiting mentor decision”, “Payment declined”, “Cancelled — refund in progress” and “Cancelled after the deadline — no refund”. Use it for the mentor page state, “Draft” or “Published”, and for the existing admin “Connected” label. Sources: book-and-pay UI/UX; mentor-pages UI/UX; existing `/admin`.

## 3. When not to use

Do not use a badge for an action: use Button or Link. Do not use it for a message that needs a decision or explanation: use Alert, or text near the field. Do not put every piece of metadata in a badge. Author and time are plain metadata text. Never show ratings, stars or invented reputation in a badge. Status-to-tone mapping for bookings belongs to the future StatusBadge, in the pattern stage. Sources: task What to avoid (everything in pills); reference R02.3; N02 (no ratings); platform F6.

## 4. Anatomy

A text label in the metadata role (12/16, medium). It has 8 px inline and 2 px block padding, a 1 px border and a 6 px radius, not a pill. An optional 12 px icon goes before the text, and it is decorative: the text carries the meaning. Sources: user decision 2026-10-31 (radius-sm); approved stage-0 Q2 (metadata role); WCAG 1.4.1.

## 5. Variants

All six existing variants are retained. Choose by weight, not by colour meaning:

- default (filled primary): a positive end state that should stand out, such as “Published”.
- secondary: a neutral state, such as “Draft” or “Cancelled after the deadline — no refund”.
- destructive: a failure that needs attention, such as “Payment declined” or “Refund failed”. It uses an explicit fill and text pair.
- outline: waiting on someone, such as “Awaiting mentor decision”.
- ghost: low emphasis inside dense rows.
- link: only with `asChild` on an anchor to a status detail.

Sources: existing package variants (task rule 12); reference R01.5 (hierarchy); token contrast repairs (T01). Weight-to-state guidance: user decision 2026-10-31, as an interim rule until the StatusBadge mapping in F6.

## 6. States

A static badge has no interaction states. Disabled, loading and selected do not apply because a status is read-only. A badge rendered as a link (`asChild`) has hover (variant fill or underline), focus (the full 3 px ring with a 2 px offset) and pressed (same as hover). `aria-invalid` adds the destructive border for an error label. The text must still say what failed. Sources: task stage 2; WCAG 1.4.1, 2.4.7; token contrast repairs.

The hover and focus samples use documentation-only `data-preview-state` attributes, wired to the same declarations as the real pseudo-classes.

## 7. Behavior and accessibility

A static badge is plain text inside its row. A screen reader reads it in sequence, so place it after the object name. A link badge is reachable by Tab, opens with Enter, and keeps a 24 px minimum height. Do not use `role="status"` for a badge that is rendered once. Use a live region only when the status changes while the person is on the page. Sources: WCAG 1.3.2, 2.1.1, 2.5.8, 4.1.3.

## 8. Content

Use the specified status wording, a past participle or a short phrase, at most about 40 characters; the longest specified label is “Cancelled after the deadline — no refund” (39). Use sentence case and no trailing punctuation. Text does not wrap by default. For a longer language, allow wrapping with `whitespace-normal` rather than truncating a status. Sources: book-and-pay UI/UX labels; U01.1. The 40-character guidance: user decision 2026-10-31.

## 9. Responsiveness

At 320 px the badge wraps to the next line beside its object (`flex-wrap` on the row) and never overflows. At 768 and 1440 px it stays on the object's line. Sources: approved stage-0 Q3; WCAG 1.4.10.

## 11. Code

Minimal:

```tsx
import { Badge } from '@mentio/ui/components/badge';
<Badge variant="secondary">Draft</Badge>
```

Product composition:

```tsx
<p className="flex flex-wrap items-center gap-within-group">
  Booking with Alex, 6 November 2026 at 18:00 <Badge variant="outline">Awaiting mentor decision</Badge>
</p>
```

Sources: book-and-pay UI/UX; package API.

## 13. Related

People confuse it with Button: a badge never triggers an action. StatusBadge maps booking states to badges in the pattern stage. Alert is used for explanations. Patterns: booking and payment recovery; cancellation; publication; earnings. Sources: approved stage-0 inventory; platform F6.
