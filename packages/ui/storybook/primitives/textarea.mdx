# Textarea

## 1. Purpose

Capture the technical context of a question or description across several lines. Source: book-and-pay UI/UX; mentor-pages UI/UX; R03.

## 2. When to use

Use it for the mentee question before payment and the mentor description of work they have done. Source: book-and-pay UI/UX; mentor-pages UI/UX; R03.

## 3. When not to use

Use Input for a rate, email or one URL. Use the future message composer for sending session messages; Textarea alone does not implement sending or a reply thread. Sources: platform F4, approved component inventory and task How to choose requirements.

## 4. Anatomy

A native textarea with a neutral opaque surface, minimum height, boundary, editable content, resize behavior and full focus ring. FormField supplies the visible label, hint, requirement and error. Sources: package API, task field anatomy; WCAG 1.3.1/3.3.2.

## 5. Variants

One visual style with the retained 64 px minimum height and medium radius. rows and native constraints describe content needs; no compact or code-editor variant is introduced. Sources: approved stage-0 Q2 and package API; no added variants are authorized.

## 6. States

Default, hover, focus, disabled, read-only, pending via aria-busy and invalid via aria-invalid. Explain disabled editing beside the field. Read-only content stays available to copy. Loading is not success. A text selection or pressed key is native editing behavior, not a selectable or toggled Textarea state. Sources: task stage 2; WCAG 1.4.1/2.4.7/3.3.1; approved contrast corrections and U02.1.

The hover and focus previews use documentation-only data-preview-state attributes wired to the same declarations as real pseudo-classes. Sources: task stage 2 frozen-state requirement; approved Q2.

## 7. Behavior and accessibility

Use a visible associated Label and keep the hint and error linked. Tab moves between controls; Enter adds a line and must not submit a question silently. Preserve native selection, clipboard and resizing. Error announcements belong to the consuming form; the low-level control does not announce its own validation. Sources: HTML native control semantics, WCAG 1.3.1/2.1.1/2.4.7/2.5.8/3.3.1/3.3.2/4.1.2.

## 8. Content

Ask for what failed, expected behavior and what the mentee already tried. The booking question has a 20–5,000 character contract; the mentor description uses its own schema. Keep saved text, line breaks and long technical names; do not silently shorten a question. Label text wraps in a longer language rather than becoming a placeholder. Sources: U01.1, task Content and longer-language requirements; book-and-pay UI/UX; mentor-pages UI/UX; R03.

## 9. Responsiveness

At 320 px, fit the column, preserve line breaks and let long tokens wrap. At 768/1440 px, keep surrounding prose within the approved reading width. Grow vertically rather than widening the screen; allow the native resize behavior. Sources: approved stage-0 Q2/Q3; WCAG 1.4.10.

## 11. Code

Minimal association:

```tsx
import { Textarea } from '@mentio/ui/components/textarea';
import { Label } from '@mentio/ui/components/label';
<Label htmlFor="question">Your question</Label>
<Textarea id="question" name="question" />
```

Product composition:

```tsx
import { FormField } from '@mentio/ui/backend/forms';
import { Textarea } from '@mentio/ui/components/textarea';
<FormField label="Your question" required
  description="Include the error, expected behavior and what you have tried.">
  <Textarea name="question" minLength={20} maxLength={5000} />
</FormField>
```

The snippets compose real package components; import Input, Textarea and Label from their component subpaths and FormField from `@mentio/ui/backend/forms` when used. Sources: approved import contract; book-and-pay UI/UX; mentor-pages UI/UX; R03.

## 12. Good and bad

<table><thead><tr><th>Good</th><th>Bad</th></tr></thead><tbody><tr><td>A visible question label and technical-context hint; line breaks remain editable.</td><td>A single-line input or a placeholder-only question: the user cannot review context comfortably.</td></tr></tbody></table>

The bad case is explained rather than rendered as an inaccessible interactive control. Sources: task good/bad and no-accessibility-violations requirements; WCAG 3.3.2/4.1.2.

## 13. Related

Input is for one short value. FormField associates the message anatomy. CrudForm owns submission and server errors. MessageComposer remains future E04 work. Sources: approved stage-0 component/pattern inventory, platform F4 and task How to choose.
