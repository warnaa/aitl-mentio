# ErrorMessage

## 1. Purpose

Tell a person that a region or page could not be loaded, what that means and whether trying again can help. Sources: existing `backend/feedback`; task Content (errors: what happened and what to do).

## 2. When to use

- A list, detail or page that failed to load, such as “We could not load your bookings”.
- The existing admin “Database unavailable”.
- DataTable when its request fails.

Sources: existing DataTable and `/admin`; book-and-pay UI/UX; platform F3.

## 3. When not to use

- For a field validation error, use FormField's error.
- For a failed action on a loaded page (payment declined, slot taken), use Alert near the action.
- For a missing record or missing access, use the detail view's not-found-or-no-access state.
- Never use a toast.

Sources: platform F4; book-and-pay UI/UX; task How to choose (an error that needs action is never a toast).

## 4. Anatomy

A box with the approved error surface (destructive at 5%), a full 1 px destructive border, a 10 px radius and 16 px padding. Inside:
- the title in the destructive role, medium weight (default “Something went wrong”),
- the message in the muted role, up to 65ch,
- an optional outline “Try again” Button.

Sources: user decision 2026-10-31 (full border); tokens (`--error-surface`, measured with T01); retained base geometry.

## 5. Variants

There are no visual variants. Retry appears only when `onRetry` is passed and trying again can help. Do not offer it for a configuration error such as a missing database. Sources: package API; existing `/admin`.

## 6. States

There is one state: failed. The retry Button keeps Button states. While retrying, show LoadingMessage or the pending Button state, and replace the error with content on success. The title text names the failure, so colour is not the only signal. Sources: WCAG 1.4.1; Button states.

<Unstyled><Canvas of={Stories.States} /></Unstyled>

## 7. Behavior and accessibility

It has `role="alert"`, so it is announced when it appears in place of the loading state. Focus does not move. The retry Button is reachable with Tab and activated with Enter or Space. Measured contrast: the title is at least 4.76:1 and the message at least 5.45:1 on the error surface in both themes. Sources: WAI-ARIA alert role; WCAG 1.4.3, 2.1.1, 4.1.3; tokens contrast table.

## 8. Content

- The title says what failed: “We could not load your bookings”, not just “Error”.
- The message says what to do and what is safe: “Check your connection, then try again. Your bookings are not affected.”
- Never show stack traces or codes, and never blame the person.
- Long text wraps.

Sources: task Content; U01.1; security baseline (never leak internals).

## 9. Responsiveness

It fills its container at every width. At 320 px the title and message wrap, and the retry Button stays a full-size target. Sources: approved stage-0 Q3; WCAG 1.4.10, 2.5.8.

## 11. Code

```tsx
import { ErrorMessage } from '@mentio/ui/backend/feedback';
<ErrorMessage title="We could not load your bookings"
  message="Check your connection, then try again. Your bookings are not affected."
  onRetry={reload} />
```

Sources: book-and-pay UI/UX; package API.

## 13. Related

Alert reports action failures on a loaded page. FormField errors are for single fields. EmptyState covers nothing to show. DataTable renders ErrorMessage. Patterns: list with filters; detail view; form (server error). Sources: approved stage-0 inventory.
