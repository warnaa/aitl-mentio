# RadioGroup

## 1. Purpose

Let a person compare a few exclusive options side by side and pick exactly one. Sources: approved stage-0 inventory (task minimum); WAI-ARIA APG radio group.

## 2. When to use

Use it when two to five exclusive options must all stay visible and each option needs its own explanation. The documented product example shows the two booking lengths with their prices. The book-and-pay spec currently uses Select on that screen, so this is the alternative presentation, not the current screen. Sources: approved stage-0 inventory; book-and-pay UI/UX; brief R01. The two-to-five option range: user decision 2026-10-31.

## 3. When not to use

Use Select when the list is long or space is short, and on the booking screen, which the spec defines as a select. Use Checkbox for an independent yes/no choice. Use Button for an action that happens at once. Sources: book-and-pay UI/UX; WAI-ARIA APG; task How to choose.

## 4. Anatomy

The group container (`role="radiogroup"`) is named by a visible heading through `aria-labelledby`. Each option has a 16 px circular control and a visible `Label`, and a dot marks the selected option. An optional group hint or error is linked to the group. Options are 8 px apart. Sources: package API; WAI-ARIA APG; reference R01.1 and R02.3 (space-within-group).

## 5. Variants

One appearance. `orientation` is behavior, not a new look: vertical for options that need explanations, horizontal for short options. Layout comes from utilities. Sources: package API; approved stage-0 Q2.

## 6. States

Default is an opaque circle with the input border. Hover strengthens the border to the ring role. Focus shows the full 3 px ring with a 2 px offset. Selected shows a filled dot and the primary border, so it does not rely on colour alone. Disabled blocks the group: the persistent hint says why, for example “Bookings are temporarily switched off.” Error sets `aria-invalid` on the group and items, with a linked message such as “Choose 25 or 50 minutes.” Loading and pressed are not radio states. Sources: task stage 2; WCAG 1.4.1, 2.4.7, 3.3.1; token contrast repairs.

The hover and focus samples use documentation-only `data-preview-state` attributes, wired to the same declarations as the real pseudo-classes.

## 7. Behavior and accessibility

Tab enters the group once, on the selected option or the first one. The arrow keys move between options and select them. Tab leaves the group. Clicking a label selects its option. A screen reader announces the group name, the option label, “radio button”, “2 of 2” and checked or not checked. Each 16 px circle relies on its label row for the 24 px target. Sources: WAI-ARIA APG radio group; WCAG 2.1.1, 2.4.3, 2.5.8, 4.1.2.

## 8. Content

The group heading asks or names the choice: “Session length”. Option labels state the value and its consequence: “25 minutes — 120 zł”. Labels may wrap. Do not shorten them for a longer language. Order options by value, not by preference. Sources: U01.1; book-and-pay UI/UX; task Content requirements. Ordering by value: user decision 2026-10-31.

## 9. Responsiveness

At 320 px use the vertical orientation, with labels wrapping beside each circle. Horizontal groups must wrap, never overflow. At 768 and 1440 px either orientation is fine if each label stays next to its circle. Sources: approved stage-0 Q3; WCAG 1.4.10.

## 11. Code

Minimal:

```tsx
import { Label } from '@mentio/ui/components/label';
import { RadioGroup, RadioGroupItem } from '@mentio/ui/components/radio-group';
<p id="length-legend">Session length</p>
<RadioGroup name="lengthMinutes" aria-labelledby="length-legend">
  <div className="flex items-center gap-within-group"><RadioGroupItem id="len-25" value="25" /><Label htmlFor="len-25">25 minutes — 120 zł</Label></div>
  <div className="flex items-center gap-within-group"><RadioGroupItem id="len-50" value="50" /><Label htmlFor="len-50">50 minutes — 240 zł</Label></div>
</RadioGroup>
```

The product example is the same composition with a group hint linked through `aria-describedby`. On the booking screen, use Select as specified. Sources: book-and-pay UI/UX; package API.

## 13. Related

Select is used for the booking length on the specified screen. Checkbox handles independent choices. FormField handles single-control fields. Patterns: form; booking and payment recovery. Sources: approved stage-0 inventory.
