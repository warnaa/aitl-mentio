# StatusBadge

## 1. Purpose

Show the state of a record with a consistent weight per kind of state, so lists can be scanned. Sources: platform F6.

## 2. When to use

- The booking status on `/rezerwacje` and the booking details.
- The mentor page status (draft or published).
- The slot visibility in the mentor's slot list.

The concept owns the state → tone and label map. Sources: platform F6; book-and-pay and mentor-pages UI/UX.

## 3. When not to use

- For any label that is not a state, use Badge.
- For an explanation or a failure that needs action, use Alert.
- Never show ratings.

Sources: Badge page; N02.

## 4. Anatomy

A Badge with a text label and a tone. There is no icon by default, because the text carries the meaning. Sources: Badge page; WCAG 1.4.1.

## 5. Variants

Tones and their Badge weights:
- `neutral`: secondary (draft, cancelled, expired).
- `waiting`: outline (awaiting payment, awaiting a decision, in progress).
- `success`: filled (published).
- `danger`: destructive (declined, refund failed).

Sources: platform F6 tones; user decision 2026-10-31 (weight guidance).

## 6. States

It is read-only: hover, focus, disabled, selected and loading do not apply. A change of state renders a new label. Sources: platform F6.

<Unstyled><Canvas of={Stories.States} /></Unstyled>

## 7. Behavior and accessibility

It is plain text in reading order, exposing `data-tone` for tests. It is not a live region. Colour is never the only signal. Sources: WCAG 1.3.1, 1.4.1.

## 8. Content

Use the spec's status wording in sentence case, at most about 40 characters, for example “Awaiting mentor decision”. A pending refund reads “refund in progress”, never “refunded” (B9). Sources: book-and-pay UI/UX; user decision 2026-10-31.

## 9. Responsiveness

As Badge: it wraps beside its object, and the long-label classes allow a longer language to wrap. Sources: WCAG 1.4.10.

## 11. Code

```tsx
import { StatusBadge } from '@mentio/ui/backend/feedback';
const { tone, label } = bookingStatus[booking.status]; // concept map, built with E02
<StatusBadge tone={tone} label={label} />
```

Sources: platform F6; book-and-pay UI/UX.

## 13. Related

Badge is the primitive. Alert gives explanations. Patterns: Booking and payment recovery, Cancellation, Publication, Availability. Sources: approved stage-0 inventory.
