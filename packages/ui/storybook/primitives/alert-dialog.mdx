# AlertDialog

## 1. Purpose

Ask a person to confirm an action they cannot simply undo, and show its consequence before they commit. Sources: platform F5 (confirmed actions); WAI-ARIA APG alert dialog.

## 2. When to use

- Removing an availability slot on `/mentor/terminy`.
- Cancelling a booking, where the dialog states the expected result, such as “You will receive a full refund of 120 zł”.

Sources: mentor-pages UI/UX (slot removal); book-and-pay UI/UX (cancellation with expected refund); platform F5.

## 3. When not to use

- Do not use it for reversible actions such as saving a draft or unpublishing a page: act, then show the result.
- Do not use it for information alone: use Dialog or Alert.
- Do not use it for a choice between equal options: use RadioGroup.
- Do not stack a second confirmation for the same action.

Sources: platform F5; task How to choose; user decision 2026-10-31 (reversible actions such as unpublishing get no confirmation).

## 4. Anatomy

- The same scrim and opaque panel as Dialog.
- `AlertDialogHeader` holds `AlertDialogTitle` (16/24 semibold): a question naming the object and its date.
- `AlertDialogDescription` (14/20, muted) gives the consequence.
- `AlertDialogFooter` holds `AlertDialogCancel` (outline, names what is kept) and `AlertDialogAction` (destructive for removal or cancellation; verb and object).
- There is no close icon. Escape cancels.
- `AlertDialogMedia` (a 64 px icon tile) is exported but not used: decorative icons are excluded.

Sources: user decisions 2026-10-31; task delete-confirmation rules; reference A01.3.

## 5. Variants

One size, by user decision on 2026-10-31. The generated small size was removed. The Action can take any Button variant: `destructive` for removing or cancelling, `default` for a consequential but non-destructive confirmation. Sources: user decision; Button variants.

## 6. States

- Closed and open.
- Pending: both buttons disabled, the Action reads “Removing slot…” with `aria-busy`, and a status line says what is happening. Keep the dialog open by preventing the Action's default close and closing it on success.
- Error: an Alert inside the dialog, for example “This slot is held by a booking in progress”, with only the way out left.
- Success: the dialog closes and a status message appears next to the list.

Button states (hover, focus, disabled) come from Button. Sources: platform F5 (duplicate guard); mentor-pages edge case `409 slot_held`; reference R02.4.

## 7. Behavior and accessibility

The content has `role="alertdialog"`, named by its title and described by its description.
1. On open, focus moves to the Cancel button, the least destructive choice.
2. Tab cycles between Cancel and the Action.
3. Escape cancels. Clicking the scrim does nothing, so the decision is never made by accident.
4. Focus returns to the trigger.

The page behind is hidden and does not scroll. Sources: WAI-ARIA APG alert dialog; WCAG 2.1.2, 2.4.3, 3.3.4, 4.1.2.

## 8. Content

- The question names the object: “Remove the slot on Thursday, 6 November 2026 at 18:00?”
- The description gives the consequence, with amounts: “You will receive a full refund of 120 zł.”
- The Action is a verb and object, “Remove slot”, never “OK” or “Yes”.
- Cancel names what is kept: “Keep slot”, “Keep booking”.
- Long titles and labels wrap.

Sources: task delete confirmation (object named, cancel easy to find, verb on the delete button); book-and-pay UI/UX; U01.1.

## 9. Responsiveness

- At 320 px buttons stack at full width with the Action first, the Cancel below it, and long labels wrap.
- From 640 px they sit in a right-aligned row with Cancel first and the Action last.
- At 768 and 1440 px the width is at most 32rem.

Sources: reference R01.5; approved stage-0 Q3; WCAG 1.4.10.

## 11. Code

Minimal:

```tsx
import { AlertDialog, AlertDialogAction, AlertDialogCancel, AlertDialogContent, AlertDialogDescription, AlertDialogFooter, AlertDialogHeader, AlertDialogTitle, AlertDialogTrigger } from '@mentio/ui/components/alert-dialog';
<AlertDialog>
  <AlertDialogTrigger asChild><Button variant="outline">Remove slot</Button></AlertDialogTrigger>
  <AlertDialogContent>
    <AlertDialogHeader><AlertDialogTitle>Remove the slot on Thursday, 6 November 2026 at 18:00?</AlertDialogTitle>
      <AlertDialogDescription>Mentees will no longer see this time on your page.</AlertDialogDescription></AlertDialogHeader>
    <AlertDialogFooter><AlertDialogCancel>Keep slot</AlertDialogCancel>
      <AlertDialogAction variant="destructive" onClick={removeSlot}>Remove slot</AlertDialogAction></AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>
```

For an asynchronous removal, control `open`. Call `event.preventDefault()` in the Action's `onClick`, start the request, show the pending state, and close on success. Sources: mentor-pages UI/UX; platform F5.


## 12. Good and bad

Sources: task delete confirmation; WAI-ARIA APG alert dialog; book-and-pay UI/UX.

## 13. Related

Dialog is for non-decisions. Alert is for feedback. Button is the trigger and the actions. Patterns: delete confirmation; cancellation; availability. Sources: approved stage-0 inventory.
