# Start here: how to build a Mentio screen

This Storybook is the manual for building Mentio screens. It is written for three readers: a developer building a screen, an AI agent building a screen, and a designer checking that a screen follows the system. Agents read the short version first: `docs/design-system.md`.

## The product in three sentences

Mentio connects developers who are stuck on one specific problem with experienced engineers, for a paid 25- or 50-minute session held in text (brief: Decision summary; R01; N01). A mentee finds a mentor by their public work, not by ratings, picks a published slot, writes the question and pays before the session (D02, D09, N02, R03). The mentor accepts or declines, answers in a text conversation, and sees what they earned (E03–E05; R06).

**Character:** readable, warm, focused. **Anti-character:** generic, flashy, distracting. Source: `lekcja-06/referencje.md` (confirmed character words).

What the character means on screen:
- **Readable:** dense lists with thin separators; code in monospace; one filled primary action per view (R01.1–R01.3, R01.5).
- **Warm:** warm grey surfaces; friendly second-person text in words, not decoration (R01.4, U01.1).
- **Focused:** the conversation leads the session; feedback appears next to what changed; no decorative emoji, gradients or sparkles (R02.1, R02.4, R02.5, A01).

## Five steps to build a screen

1. **Find the pattern.** Start from a pattern page (Form, List with filters, Detail, Delete confirmation, Booking and payment recovery, Cancellation, Mentor decision, Conversation and reply, Next-visit settlement, Earnings) and the epic page for your screen. If a screen story already exists under Product, copy its composition. Source: task stage 4.
2. **Choose components with How to choose.** Use the table below for imports and the *When* columns, and the How to choose page when two components seem to fit. Never add a component or variant for one screen (Contributing). Sources: task rule 6; AGENTS.md (one designated home per component).
3. **Use semantic tokens only.** Colours, spacing, type, radii and motion come from the role tokens on the Foundations pages (`bg-background`, `text-muted-foreground`, `gap-between-groups`, `p-panel`, `max-w-(--prose-max-width)`). No hex, rgb, hsl or oklch values; no palette classes (a colour family with a shade, such as zinc 900 on a background utility); no arbitrary values (a utility followed by a value in square brackets, such as 13 px of padding). `npm run check:tokens` fails otherwise. Source: task rule 3.
4. **Design every data state.** Loading, empty, error, partial data, many records and long text — and for forms, pending, field error, server error and no network. The screen stories show each state; your screen needs the same. Sources: task stage 3; platform F1–F4.
5. **Check What to avoid.** Read it before you open a pull request, then run the commands under Contributing. Source: task stage 4.

## Where things live

- **Foundations:** colour, typography, spacing and layout, shape and depth, motion, icons, themes.
- **Primitives:** base components, plus the shared panel layer (`@mentio/ui/backend/*`) that every screen reuses for API calls, forms, lists, actions and feedback.
- **Product:** components tied to one concept, and full-screen stories with a state map for each epic.
- **Patterns:** how components combine for a recurring task, with every state as a story.

Sources: approved stage-0 menu; AGENTS.md (reusable API and UI layer).
