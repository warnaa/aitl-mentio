# Mentio design system — reference for agents

Read this file first when you build or change a screen. It is the short version of the Storybook in `packages/ui`, where every component has a 13-section page with the sources behind each rule. Run it with `npm run storybook` (port 6006). Start with **Design system › Start here**.

The component table is generated from `packages/ui/storybook/design-system/inventory.ts`, the same list as Start here and Components. Change the inventory, then run `npm run docs:agent`; `npm run check:agent-doc` fails when this table is stale.

## Character

Mentio connects developers stuck on one specific problem with experienced engineers, for a paid 25- or 50-minute session held in text. Mentees choose mentors by public work, never by ratings, pick a published slot, write the question and pay first. The mentor accepts or declines, answers in the conversation, and sees what they earned.

- **Character:** readable, warm, focused.
- **Never:** generic, flashy, distracting.

Ten decisions (`lekcja-06/referencje.md`, the brief):
1. Dense lists with thin row separators (R01.1, R01.3).
2. Code and file names in monospace (R01.2).
3. Warm neutral, flat, opaque surfaces; no brand hue, no gradients or glass (R01.4, A01).
4. One filled primary action per view; secondary actions quieter (R01.5).
5. In a session the conversation leads; task navigation is separate (R02.1, R02.6).
6. Replies keep a link to their message; author and time are always visible (R02.2, R02.3).
7. Second person, warm, plain; no interface emoji or sparkles (U01.1, R02.5, A01.3).
8. Feedback appears next to what changed, with 150 ms colour transitions only; no duplicate pop-ups (R02.4, U02.1).
9. No ratings, course modules, progress percentages or certificates (N02, A02, A03).
10. The app speaks Polish (R15); copy and formatting arrive through props. Components own no copy.

## Build a screen in five steps

1. **Find the pattern and the epic page.** The patterns are Form, List with filters, Detail, Delete confirmation, Booking and payment recovery, Cancellation, Mentor decision, Conversation and reply, Next-visit settlement and Earnings. If a screen story exists under **Product › E0x › Screens**, copy its composition.
2. **Choose components** from the table below. When two fit, use the guide under “If… use…”.
3. **Use semantic tokens only** (below). `npm run check:tokens` fails on anything else.
4. **Design every data state:** loading, empty, error, partial, many and long; for forms also pending, field error, server error and no network.
5. **Check “What to avoid”**, then run the commands.

Shared layer rules (AGENTS.md):
- Every `fetch` goes through `apiCall` (`@mentio/ui/backend/api`).
- Forms are CrudForm, one-click server actions are ActionButton, and lists are DataTable.
- Loading, error and empty states come from `backend/feedback`.
- Panel screens sit in PanelShell; public pages use AccountNav plus the public components.

## Semantic tokens

Use these through Tailwind utilities, or `var(--name)` in the package CSS. Never use hex, rgb, hsl or oklch values, palette classes (a colour family with a shade) or square-bracket arbitrary values.

| Purpose | Token / utility |
|---|---|
| Page background and text | `bg-background`, `text-foreground` |
| Card, popover, panel surfaces | `bg-card`, `text-card-foreground`; `bg-popover` |
| Primary action (filled) | `bg-primary`, `text-primary-foreground`; hover `--primary-hover` |
| Quieter surfaces, selected rows, code background | `bg-muted`; secondary text `text-muted-foreground` |
| Hover tint of quiet controls | `bg-accent`, `text-accent-foreground` |
| Errors and destructive actions | `text-destructive`, `bg-destructive`, `text-destructive-foreground`; error tint `--error-surface` |
| Borders, inputs, focus ring | `border-border`, `border-input`, `--ring` with `--focus-width` 3 px and `--focus-offset` 2 px |
| Task navigation | `bg-sidebar`, `text-sidebar-foreground`, `--sidebar-*` |
| Space inside a group (8 px) | `gap-within-group` |
| Space between groups (16 px) | `gap-between-groups` |
| Inside a panel (24 px) | `p-panel` |
| Between sections (32 px) | `gap-section` |
| Widths | `--content-max-width` 1152 px, `--prose-max-width` 65ch, `--viewport-small/medium/large` 320/768/1440 |
| Radii | `rounded-sm` 6 px (badge, checkbox), `rounded-md` 8 px (controls), `rounded-lg`, `rounded-xl` 14 px (card) |
| Type roles | page 24/32 semibold (`mentio-public-title`), section 20/28 semibold (`mentio-public-heading`, CardTitle), body 16/24, label 14/20 medium (`mentio-label`), metadata 12/16 (`mentio-field-description`), code 14/20 `--font-code`, numbers `tabular-nums` |
| Motion | `--motion-duration` 150 ms, colour and border only; none under reduced motion |
| Controls | `--control-height` 36 px; small 32 px; compact 24 px (the minimum target) |

Both themes (light, dark) switch on `<html class="dark">`. Dialogs and menus inherit the theme.

## If… use…

| If… | Use |
|---|---|
| It does something on this page | Button; ActionButton when it calls the API |
| It goes somewhere | Link (a real anchor) |
| One object has several secondary actions | DropdownMenu; the main action stays a visible Button |
| Two to five exclusive options must stay visible | RadioGroup; otherwise Select (the booking length is a Select) |
| One independent yes/no choice | Checkbox (there is no Switch) |
| An action cannot be undone | ActionButton `confirm` (AlertDialog) naming the consequence |
| A long form or a linkable view | A separate page, not a Dialog |
| Helpful, non-required detail | Popover; never a Tooltip for anything needed to act |
| A field value is wrong | The field error, with focus on the first error |
| An action failed and the person must act | Alert or the inline ActionButton error next to it — never a toast |
| A region failed to load | ErrorMessage with Try again |
| First load, known layout | Skeleton plus a text status; unknown layout: LoadingMessage |
| API list | DataTable (rows stack below 48rem); public mentor list: MentorDirectory |
| Different tasks | Separate pages in the task navigation (there are no Tabs) |
| Money | “240 zł”, “−48 zł”; table dates “4 Nov, 18:00”; times in Warsaw time |

## What to avoid

- **Product anti-patterns:**
  - purple gradients and glass cards (A01.1, A01.2);
  - sparkles (A01.3);
  - course modules, progress percentages and certificates (A02);
  - stars, averages and rating sorts (A03, N02);
  - cold all-grey screens (R01.4);
  - several filled buttons in one view (R01.5);
  - pop-ups repeating on-page changes (R02.4);
  - interface emoji (R02.5);
  - cluttered side navigation (R02.6).
- **Generic AI look:**
  - gradients on backgrounds, text or buttons;
  - glass and blur; glow;
  - emoji instead of icons; sparkles as the AI symbol;
  - three identical icon cards; everything in pills;
  - a card in a card; shadow as the only separator;
  - everything centred.
- **Implementation:**
  - values outside the tokens;
  - variants added on the way;
  - `div` instead of `button`;
  - a placeholder instead of a label;
  - status shown by colour only;
  - a disabled control without a visible reason;
  - a toast for an error that needs action;
  - a tooltip holding needed information;
  - a hand-written `fetch` or form;
  - fixed `id` literals (use `useId`);
  - a landmark per repeated item.

## Gaps

There is no Switch, Avatar, Tabs, Toast, Combobox, Sheet or date picker, and no E03–E05 specs (their screens follow user decisions of 2026-11-01). The 404 and error pages are not designed. Check **Design system › What is missing** before inventing anything; add to it instead.
